# Project: MovieMatch

## Quick Facts
- Stack: FastAPI + SentenceTransformers + ChromaDB (local) / Pinecone (prod) + Anthropic API.
- Purpose: Semantic movie recommendation engine. Users submit a natural language query; the app embeds it, retrieves vector-similar candidates, then uses Claude to rerank/filter them.

## Query Pre-Parsing

Every query runs through `parse_query()` in `query_parser.py` before embedding. This is a pure regex pass (<1ms, no I/O) that extracts structured tokens into a `ParsedQuery` dataclass:

- **Year/decade**: "90s" → `year_min=1990, year_max=1999`; "early 2000s", "after 1985", "last 10 years", etc.
- **Genres**: "no documentaries" → `excluded_genres=["Documentary"]`; "sci-fi" → `required_genres=["Science Fiction"]`; "animated" / "animation" → `required_genres=["Animation"]`; "live action" / "live-action" → `excluded_genres=["Animation"]` (special-cased via `_LIVE_ACTION_PATTERN` since "live action" is not a TMDB genre)
- **Certifications**: "family friendly" / "kids movie" / "children's film" / "for children" etc. → `excluded_certifications=["NC-17"]` + `certification_caveats` (soft Claude guidance to prefer G/PG/PG-13, surface R only as last resort with explicit note); "no R-rated" → `excluded_certifications=["R"]`
- **Person names**: "directed by Bong Joon-ho" → `person_names=["Bong Joon-ho"], person_department="directing"`; also handles film slang ("Spike Lee joint")
- **Title references**: `like <title>` is treated as a reference **by default** — "something like Inception", "more movies like Parasite (2019)", "movies like Krull", "sci-fi like Die Hard", "like inception but funnier" — and titles need **not** be capitalized (`movies like krull` works). The *verb* sense of "like" (subject-pronoun + like: "I like", "we like", "you'd like") is the carved-out exception via negative lookbehind. Genuinely ambiguous leftovers ("movies like the ones from the 80s") are intentionally allowed through to TMDB resolution rather than special-cased — they fail to resolve or get filtered by retrieval + Claude. Also "similar to The Godfather" and quoted `like "The Dark Knight"`. All → `reference_titles=[...]`. "in the style of Wes Anderson" → also adds to `person_names`; reference titles are injected into the Claude prompt as a `<reference_films>` block
- **Relative date hints**: "older", "classic", "more recent" → `relative_date_hints` (soft guidance injected into Claude's prompt)

**Person lookup — concurrent with embedding**: when `person_names` is non-empty, `resolve_persons()` is submitted to a `ThreadPoolExecutor` at the same time `_fetch_candidates()` starts. The TMDB round-trip (~500ms) overlaps with embedding+vector search (~220ms), then the result is awaited with a 1.5s timeout before calling Claude.

**Hard filtering**: `apply_hard_filters()` drops vector candidates that violate year, genre, or certification constraints before they reach Claude. Candidates with missing metadata are kept conservatively.

**Prompt injection**: resolved filmographies, extracted constraints, and reference titles are injected into Claude's prompt as structured XML blocks (`<constraints>`, `<reference_films>`, `<filmography>`). All user-derived strings are sanitized with `_sanitize()` (strips `<`, `>`, `&`) before injection. When all requested persons are pre-resolved, person-lookup tools are removed from the tools list entirely (hard guarantee, not a prompt-only instruction).

**Background ingestion**: after a successful person pre-fetch, `_ingest_filmography_background` is triggered in a daemon thread — same as when Claude calls `get_filmography` directly.

Key config values:
- `PERSON_LOOKUP_TIMEOUT_S = 1.5` — max wait for concurrent TMDB pre-fetch
- `PREPARSE_EXECUTOR_WORKERS = 2` — thread pool size

## Anthropic Integration
- **Round 1**: Always Haiku (`CLAUDE_FAST_MODEL`) — cheap, handles tool-free queries
- **Round 2+**: Stays on Haiku by default; escalates to Opus (`CLAUDE_MODEL`) only if `FORCE_FAST_MODEL=false` is set and non-terminal tools are invoked
- **Tools**: `search_person`, `get_filmography`, `return_results` (terminal); person-lookup tools removed from schema when filmography is pre-resolved
- **Final-round return-only**: on the last permitted round (`round_num == AGENT_MAX_TOOL_ROUNDS`) the tools list is forced to `[RETURN_RESULTS_TOOL]` in both `rerank` and `rerank_stream`, so Claude must emit results from the candidates it already has instead of burning the round on another lookup and falling through the empty exhaustion path. Fixes the "Claude loops on `search_person` → 0 results" failure where a bare/reference title (e.g. "Perfect Date") is misread as a person name.
- **Anti-hallucination**: `_filter_results()` validates returned titles against candidate + filmography sets using case-insensitive matching
- **Streaming**: `rerank_stream()` uses `_extract_result_objects()` to yield results as JSON chunks arrive

Key config values:
- `SEARCH_CANDIDATES = 15` — vector results passed to Claude
- `SEARCH_DOC_TRUNCATE = 200` — chars of each movie doc sent in prompt
- `AGENT_MAX_TOOL_ROUNDS = 4` — the final round is forced to return-only tools (see above)
- `FORCE_FAST_MODEL = true` — keeps Haiku for all rounds; set `FORCE_FAST_MODEL=false` in `.env` to re-enable Opus escalation

## Key Decisions
- Haiku-first strategy: most queries resolve in round 1 without Opus
- `tool_choice={"type": "any"}` forces Claude to always call a tool (prevents prose responses)
- **Query pre-parsing chosen over Haiku extraction**: Haiku structured extraction was prototyped but rejected — P90 latency of 1,736ms is ~9× the 200ms embedding window. Regex is <1ms and $0 cost, covering the vast majority of query patterns.
- **Person pre-fetch runs concurrently with embedding**: the TMDB round-trip (~500ms) overlaps with embedding+vector search (~220ms) via `ThreadPoolExecutor`. Net cost: ~0ms added latency for person queries that resolve within the embedding window.
- **Conditional tool schema**: when all persons in a query are pre-resolved, `search_person` and `get_filmography` are removed from the tools list passed to Claude — a hard guarantee, not a prompt-only suggestion.
- Background thread ingests filmography discoveries into vector DB for future queries (triggered both when Claude calls `get_filmography` directly and when pre-fetch succeeds)
- `rerank` and `rerank_stream` share the same prompt/logic; `rerank` is kept for non-streaming use
- Certification is stored in vector DB metadata at ingest time and displayed immediately from search results; the vector DB is the primary source of truth for ratings — the `/streaming` endpoint handles providers only. **Runtime cert backfill**: filmography films not yet ingested carry no cert in their sparse TMDB payload, so `_batch_fetch_certifications` (`main.py`) fans out `fetch_certification` calls across a bounded pool (`CERT_FETCH_WORKERS`, hard-capped by `CERT_FETCH_TIMEOUT_S`) during metadata seeding; unresolved films stay unrated and are corrected once background ingestion stores their real cert. An empty/unknown cert renders as an explicit muted "Rating not available" note (not a blank span, and never an "NR"-looking chip)
- **"More like this" pivot**: the detail overlay exposes a forked-arrow pivot icon (inline SVG `<symbol>`) next to the title, director, and each cast member. All three call `triggerSearch()` which pre-fills the input and auto-submits via `form.requestSubmit()`. Query formats: `"More movies like [Title] ([Year])"` (hits the `more like X` regex), `"Movies directed by [X]"` (hits person/directing regex), `"Movies starring [X]"` (hits person regex). No original query is appended — the pivot is intentionally standalone. **Icon sizing**: the title-row pivot (`titlePivotIcon`) and the share icon are `rem`-sized (fixed scale) so they track the MPAA cert chip across the mobile breakpoint; the inline director/cast pivots (`pivotIcon`) stay `em`-sized so they scale down to sit with the smaller `.overlay-text` name text — do not convert those to rem.
- **Share button**: a chain-link icon (`#icon-link` inline `<symbol>`, stroke-based) sits just right of the title pivot star in the overlay. `shareMovie()` uses `navigator.share` (the native share sheet) on mobile and falls back to copy-to-clipboard + a transient "Copied!" bubble (`.overlay-title-share.copied::after`) on desktop; `copyLink()` has a legacy `execCommand` fallback for non-secure contexts where `navigator.clipboard` is undefined. The shared URL (`shareUrlFor()`) is `?q=More movies like <Title (Year)>&detail=<Title (Year)>` — the query hits the reference guarantee so the film is always in the recipient's results, and `detail=` auto-opens its card (see History API decision). Uses `encodeURIComponent`, **not** `escapeHtml` (that's for HTML attributes). The share button is a `.more-link` **without** `data-query`, so the pivot-link wiring is scoped to `.more-link[data-query]` to exclude it; it's wired separately to `shareMovie()`.
- **Reference-title anchoring** (retrieval-by-document for "movies like X"): a symmetric encoder (`all-mpnet-base-v2`) can't dereference a bare title token into the film's content, so instead of retrieving on the query text we anchor on the *referenced movie's document*. Flow: `parse_query` extracts `reference_titles` → `resolve_reference_titles()` runs concurrently with embedding and is awaited with a `TITLE_LOOKUP_TIMEOUT_S` (1.5s) cap, resolving each to a TMDB id via `search_movie_by_title` → (if resolution doesn't finish in time — e.g. a cold-start TMDB call — the query silently drops to token retrieval and loses the anchor+guarantee, so the FastAPI lifespan warms the embedding model *and* the TMDB connection at startup, see `tmdb.warmup()`, to keep the first user query off the cold path) → `_fetch_candidates_anchored()` fetches each in-DB reference's stored richtext (`vector_fetch_by_ids`), re-encodes it (deterministic), and queries its neighbors at `ANCHOR_FETCH_DEPTH` (deep, for post-retrieval hard-filter headroom), dropping the anchor itself. Multi-reference queries round-robin `_interleave` the anchor lists. **Retrieval-only, no fusion/RRF**: the qualifier in "like X but funnier" is handled in Claude's rerank, not retrieval — `parse_query` sets `has_soft_qualifier`/`residual_query` (query minus reference span minus structured tokens), which widens the candidate slice to `ANCHOR_CANDIDATES_QUALIFIED` and adds a `prefer:` line to the prompt so Claude reorders *within* the anchor neighborhood. **Cold references** (resolved but not yet ingested) fall back to the query token embedding and are background-ingested (`_ingest_reference_background`, quality gate bypassed via `ingest_single(force=True)`) so they're anchorable next time. **Always-append guarantee (gated to anchored refs)**: a referenced film that is in the vector DB is emitted in the results — appended after the stream (even past the candidate limit) if Claude's rerank didn't surface it (`_reference_guarantee_cards`, rich card from the anchor doc). **Cold references are NOT appended**: we only have a resolved TMDB id, which for an ambiguous phrase may be a wrong match, and appending it would bypass Claude's filtering — so cold refs are background-ingested instead and become guaranteed on the next search.
- **Filmography metadata seeding**: the metadata lookup dicts in `search_stream` (`main.py`) are keyed by lowercased title, built by `_build_metadata_lookups` and seeded by the shared `_seed_filmography_metadata` helper. For filmography movies not in the top-N vector candidates, seeding does a batch `vector_fetch_by_ids` call using the TMDB IDs carried in the filmography payload — this retrieves the full document (overview, genres, director, cast) for any film already in the vector DB regardless of its similarity rank. Films not yet ingested fall back to the sparse poster+year from the TMDB filmography response, with cert backfilled at runtime (see certification note above). **Mid-stream discoveries**: films Claude finds by calling `get_filmography` itself (not pre-resolved) are surfaced from `rerank_stream` as a `{"__filmography": [...movies...]}` sentinel *before* the result items that reference them; `search_stream` feeds that payload through the same `_seed_filmography_metadata` helper so those titles get poster/cert too — without it both fields render blank for tool-discovered titles.
- **Card/overlay poster resilience**: a missing `poster_path` OR a 404 at the TMDB origin both fall back to the film-reel glyph placeholder (`posterFallback()` swaps the broken `<img>` in place, keeping the poster frame) rather than removing/collapsing the poster. An offline audit (`tools/audit_posters.py`, read-only) HEAD-checks every stored poster against the CDN — origin-stale rate measured at ~0.08% (all transient), and ~0.6% of vectors have no `poster_path` stored at all; the placeholder covers both.
- **Clear-query button**: the search input is wrapped in a `.input-wrap` (`position: relative`) so a bare `&times;` button (`#clearBtn`) overlays its right edge. `toggleClearBtn()` shows it only when the input is non-empty and is called from every path that sets `input.value` programmatically (`triggerSearch`, `restoreResults`, the empty-state `popstate` reset, the `?q=` deep-link runner) plus the live `input` event. Clicking it clears the value, re-hides itself, and refocuses. The rule is scoped `.search-form .clear-btn` to out-specify the shared `.search-form button` styling (otherwise it inherits a white box + padding).
- **Mock search**: typing `__mock__` as the query bypasses the backend entirely and renders five hardcoded results through the same `appendResult()` path as live searches. Useful for frontend-only development without a running server. All mock code lives in one delimited block in `app.html` (`── Mock search (dev only) ──` → `── End mock ──`); it is deliberately kept inline rather than split into a `mock.js` because the file is an intentional self-contained monolith (no `StaticFiles` mount — it's served as an in-memory string) and a lazy `import()` would break `__mock__` from `file://`. **No network calls**: fixtures carry inline `providers` *and* `scores` arrays, and `runMockSearch()` deliberately skips `batchPrefetchStreamingProviders()` — otherwise the mock would POST to `/streaming/batch` and hit the Watchmode API. `renderStreamingProviders()`/`renderScores()` short-circuit on those inline arrays before touching the cache or network. The short-circuit is an inline check on the result object, *not* pre-seeding `streamingCache`: seeding is keyed on `userCountry`, which `/region` mutates asynchronously, so a late region resolve would miss the key and leak a live fetch. The five fixtures cover every streaming render branch (linked logo chips, rent/buy-only priced chips, empty → "not available in <region>") and a partial score set; provider entries carry inline `url` (and `price` on rent/buy) so the deep-link path renders offline, with one deliberately unpriced entry. `/region` still fires on page load — it's independent of the query and supplies the region name that branch displays.
- **Browser back button / History API**: `app.html` uses `history.pushState` / `popstate` so the back button navigates between searches and overlay detail views. Each search pushes `{type:"search", query, results, scrollY}` with URL `?q=<query>`; opening the detail overlay pushes `{type:"overlay", ..., overlayIndex}` with URL `?q=<query>&detail=<Title (Year)>`. **`detail=` carries the "Title (Year)" key, not the numeric index** — a stable, shareable pointer to the film that survives non-deterministic result ordering (the numeric `overlayIndex` still lives in the history *state object* for internal restore; only the URL is title-based). `movieDetailKey()` builds this key and is the single source of truth for the `detail=` param, the share link, and deep-link matching. Back from overlay closes it (results remain); back from a search restores the previous search's results instantly from the cached state object without a new API call. `triggerSearch()` does NOT call `closeOverlay()` — the form submit handler calls the DOM-only `closeOverlayUI()` directly to avoid a race between `history.back()` and the subsequent `history.pushState()`. **Carousel navigation (arrows, swipe, dots) adds no history entry, but now updates the URL** to name the open card via `replaceState` (all carousel paths funnel through `navigateOverlay()` → `syncOverlayUrl()`), so the address bar stays copy-shareable at every card while back still closes the overlay in one step. `?q=` deep links auto-run the search on page load; a `?detail=<Title (Year)>` on the URL (a shared link) is stashed in `pendingDetailOpen` and consumed once the results render (`maybeAutoOpenDetail`, matched by key not index) to auto-open that card.
- **Embedding model is pre-baked into the Docker image**: the `Dockerfile` downloads the SentenceTransformers weights (~418MB) at *build* time. Previously nothing pre-fetched them, so the first `get_model()` call downloaded them at **runtime** — and since the `api/app.py` lifespan warms the encoder at startup precisely to keep the first query off the cold path, that put a 418MB **anonymous** HuggingFace Hub download on every container cold start (the source of the "unauthenticated requests to the HF Hub / set a `HF_TOKEN`" warning), under the lower unauthenticated rate limit, with startup depending on huggingface.co being reachable. `HF_TOKEN` was **not** the fix — `all-mpnet-base-v2` is public, so a token only raises rate limits; the download itself was the problem. Two ordering constraints, both regression-tested: the prefetch `RUN` sits **above** `COPY . .` (otherwise every app-code edit busts the 418MB layer and each deploy re-downloads), which means it can't read `config.py` and the model name is duplicated as `ARG EMBEDDING_MODEL` — kept honest by `tests/test_dockerfile.py`; and `ENV HF_HUB_OFFLINE=1` sits **below** it (set earlier it blocks the download it exists to make unnecessary). Offline mode also makes a name drift fail loudly at startup instead of silently re-downloading. Locally the warning is harmless — the weights are already in `~/.cache/huggingface` — and `HF_HUB_OFFLINE=1` silences it.
- **Watchmode monthly counter is keyed by month, not reset**: `_counts` in `watchmode.py` is `{"YYYY-MM": int}` (12 months retained, pruned oldest-first), persisted to `LOG_DIR/watchmode_calls.json`. There is no rollover check anywhere because there is nothing to reset — the month is the *key*, resolved at write time, so the first call in a new month creates a new entry. The previous design kept a single count plus a month *label* and only re-checked that label at import; a Railway container runs for weeks without re-importing, so it carried the old total forward and then re-stamped it with the new month on the next write, corrupting the file permanently (a redeploy couldn't fix it — the stale count now *looked* current). Local dev never reproduced it: the dev server is killed nightly, so no process was ever alive across a boundary. `get_stats()` resolves the current month at read time and always includes it in `history` (at 0 if unused, and capped to the same 12-month window `_prune_history` enforces — the zero-fill would otherwise make a 13th entry every rollover), so the panel is correct the instant the month turns. Three hardening rules the file's history now depends on: the counter is written to a temp file and `os.replace()`d into place (an in-place truncate on every API call meant a SIGTERM mid-write could destroy all 12 months, not just one number); month keys are validated against `_MONTH_KEY_RE` on load in **both** the keyed and legacy-migration branches, because letters sort after digits so a junk key lands last and the panel treats the last entry as the current month; and `_prune_history(protect=month)` runs *after* the increment, never between creating a key and using it — earlier it could delete the key the next line touched (KeyError in the request path), and without `protect` it would silently discard the call it had just recorded.
- **Monthly-usage chart replaced the budget meter**: the admin panel used to show a full-width green/yellow/red meter for the current month *above* the history rows. It plotted the same value on the same 0 → limit domain as the current-month bar directly beneath it (and `143` appeared three times on screen), so it was removed and its two real jobs folded into the chart: severity moved onto the current-month row, and its `1,000 / month limit` label moved to the right of the "Monthly history" heading — that label is now **load-bearing**, the only thing naming the domain every bar is drawn against. Rows are `month · bar · count · percent`; the percent column restates what the bar encodes and replaced the per-chart scale caption.
- **Monthly-usage chart palette is measured, not chosen** (`tools/validate_palette.py`, validated against the panel's `#1a1a1a` surface): past months neutral `#6b6b66`; the current month carries a **blue → yellow → red** severity ramp at the meter's old 50% / 80% cutoffs — `--usage-safe #3987e5`, `--usage-warning #fab219`, `--usage-critical #f4695f`. **Not green/yellow/red**: green↔yellow measured 6.6 OKLab ΔE under deuteranopia, so "safe" and "getting close" were effectively one color for a red-green colorblind reader; blue/yellow/red puts the worst pair at 24.4. Critical is a lighter red on purpose — every darker red tested collapsed toward the neutral history bar under *protanopia* (`#e05c5c` measured 5.0, `#e34948` 4.6), which would hide the current month exactly when it matters most; `#f4695f` clears at 9.4. Whole set ≥3:1 contrast, worst all-pairs 9.4 CVD / 19.0 normal. Earlier neutrals `#4a4a47`/`#5a5a56` looked fine by eye and failed the 3:1 floor at 1.96/2.51 — which is why the tool exists. Only the current month is ever colored, so exactly one severity class applies at a time; "current" is carried by not-gray **plus** the "so far" label, never color alone. Rows render **newest-first** so the month being actively spent sits against the heading; the backend contract stays oldest-first, so `usageHistoryMarkup` reverses a *copy* (`reverse()` mutates, and the mock hands back the same fixture object on every state switch) and reads `currentMonth` from the chronological array *before* reversing — after it, the oldest month would get the severity colour and the "so far" marker. The `.usage-history-head` (title + limit label) is emitted **inside** `usageHistoryMarkup`, below its `if (!history.length)` guard — emitted from `renderWatchmode` instead, an empty history stranded the heading and scale label over blank space. All bars share a fixed 0 → limit domain, and since each `.usage-row` is its own grid the value/percent columns must stay **fixed** widths (an `auto` column shrinks the wider current-month row's track alone and silently breaks comparability).
- **Admin mock mode (`?mock`)**: the admin panel is behind HMAC auth, so its sparse states — a fresh deploy with nothing logged, or the single-month history Railway lands in right after `watchmode_calls.json` is deleted — cannot be produced on demand against real data. `?mock` (or `?mock=<state>`) short-circuits `load()` **before any `fetch()`** and renders the whole page from inline fixtures, so it works from `file://` with no server and no login; a sticky switcher bar moves between states (`empty`, `sparse`, `two`, `safe`, `warning`, `critical`, `capped`), and a quiet **Mock / Exit mock** link in the header crosses the boundary both ways. That toggle is rendered *unconditionally* — behind the `MOCK_ACTIVE` guard the entrance would only exist once you were already through it — but still lives inside the delimited block, so one cut removes the entrance along with what it leads to. Leaving strips the query (`location.pathname`) rather than hardcoding `/admin.html`, so the round trip works over `file://` too. Mock code sits in two named fences that point at each other — behaviour in `── Mock admin (dev only) ──` → `── End mock ──`, styles in `── Mock admin styles (dev only) ──` inside the `<style>` block — and removing the mock means cutting both. The styles are **not** injected from JS: that appended them after the entire stylesheet at runtime, so `.mock-toggle.leaving` beat `.header-link:hover` purely on script timing rather than a visible decision. In the sheet the order is explicit — `.leaving` sits *below* `.header-link:hover` because both are two-class selectors and it has to win to stay amber while hovered, which is also why it carries its own `:hover`. Month keys are generated relative to *now*, so fixtures stay correct over time and the last row really is the current month — the rule the chart's severity styling depends on. The render is deferred to `DOMContentLoaded`: `_renderTableRows()` reads `US_STATE_ABBREV`, declared in a **later** `<script>` block, and the live path only reaches it after awaiting a fetch, so rendering synchronously hits that const's temporal dead zone.
- **Bot/scraper resilience**: rate limiting via `slowapi` on all public endpoints (`RATE_LIMIT` on `/recommend`, `STREAMING_RATE_LIMIT` on `/streaming` and `/streaming/batch`); security headers (`X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`) added to all responses via middleware; CORS restricted to `GET`/`POST` and `Content-Type` header only; `user_agent` field logged on every `/recommend` request.
- **Location-aware streaming**: `GET /region` resolves the client IP to an ISO 3166-1 alpha-2 country code via ipinfo.io (free tier, process-lifetime cache in `api/geo.py`). The frontend calls it once on page load — before the user types their first query — and stores the result in `userCountry`. All subsequent `/streaming` and `/streaming/batch` calls pass `country=XX` so Watchmode/TMDB return region-specific providers. URL param `?country=XX` overrides detection for testing and VPN workarounds. Watchmode cache key fixed to `providers:{title_id}:{country}` so US and non-US results don't share entries. Watchmode returns 400 (not empty array) when a title has no sources in a region; this is caught separately and logged at DEBUG, not WARNING.
- **Streaming provider deep links**: each provider chip in the overlay is an `<a>` to that *film* on that service, opened in a new tab (`rel="noopener noreferrer"`, same treatment as the Reviews score chips). The link is Watchmode's per-source `web_url`, which was already in the `/title/{id}/sources/` response we fetch — **no extra API call and no added latency**. `ios_url`/`android_url` are *not* usable: on the free tier they return the literal string "Deeplinks available for paid plans only." That costs nothing in practice — the major services' web URLs are registered **universal links**, so on iOS/Android the same anchor opens the installed app at the film. `_clean_web_url()` keeps only `http(s)` values, so a placeholder or `javascript:` value can never reach an `href`. **Dedupe is a two-stage merge**, not a discard: Watchmode emits one row per *format* (SD/HD/4K) at different prices, so a better `type` replaces outright (`sub > free > rent > buy`) while an equal type keeps the **cheapest** price and backfills a missing url/logo. **No links in the TMDB fallback** — TMDB offers only one shared JustWatch page per film/region, not a per-provider link, so `providerChip()` renders a plain `<div>` when `url` is absent rather than have a chip lie about its destination.
- **Rent/buy relabels the section**: when nothing is streamable, rent/buy options are promoted from a prose line to the same priced chips, and the section *heading* changes from "Streaming" to "Available to rent or buy" (narrowed to "…to rent" / "…to buy" when only one type is present). The heading carries the caveat, so the chips need no preamble. It's rewritten in place via `#streamingLabel`, and **every** branch of `paintProviders()` sets it explicitly rather than trusting the template default, so a re-render into an open overlay can't strand a previous film's label (regression-tested). Chips don't spell out rent vs buy — the price implies it and the heading covers the section — so the hover `title` carries the distinction ("Rent on …" / "Buy on …" / "Watch on …"). Prices come from Watchmode's `price` with no currency code attached, so `CURRENCY_BY_COUNTRY` maps `userCountry` → an ISO currency for `Intl.NumberFormat`, defaulting to USD; this assumes the price is quoted in the requested region's currency. A `null` price still renders the chip, just without an amount.
- **Credential redaction in logs (`logger.redact`)**: `requests` embeds the full request URL — query string and all — in every `HTTPError` message, so any API that authenticates by *query parameter* leaks its key through a bare `except Exception as e` log line. Watchmode (`apiKey=`) and OMDb (`apikey=`) both do; TMDB and Anthropic authenticate by header and are unaffected. `logger.redact(value)` stringifies and replaces every credential found on the `config` module with `***`. It reads config **at call time**, not import time, so tests patch `config.<KEY>` (not the consuming module's binding). Two guards matter: an **empty** secret is skipped because `"abc".replace("", "*")` interleaves the replacement between every character, and secrets shorter than `_MIN_SECRET_LEN` (8) are skipped so a short value can't riddle unrelated text with `***`. Applied at every `requests`-adjacent failure log in `watchmode.py` and `omdb.py`. **When adding a keyed API, add its config attribute to `_SECRET_CONFIG_ATTRS` and wrap its failure logs.**
- **OMDb quota/auth logging**: OMDb answers **HTTP 401 for both** a spent daily quota (`Error: "Request limit reached!"`) and a bad/unactivated key (`"Invalid API key!"`) — only the JSON body distinguishes them. `fetch_ratings` therefore inspects the body *before* `raise_for_status()`, which would otherwise collapse both into one opaque `401 Client Error` and discard the reason. Quota hits log `[omdb_quota_exhausted]` at ERROR, auth failures `[omdb_auth_failed]`; both return `{}` and are **not cached**, since each condition is recoverable (quota resets, keys get activated). Logged on **every occurrence, deliberately not deduplicated** — with a 1,000/day cap, the line count is the measure of how much demand the exhausted quota turned away. Generic failures stay at WARNING and pass through the shared `logger.redact()` (see above).
- **Reviews (critic/audience scores)**: the detail overlay has a **"Reviews"** section (just above Streaming) showing review scores as clickable brand-glyph chips in fixed order **RT → IMDb → Metacritic → TMDB**. Scores are an async supplement fetched the same way streaming is — `renderScores()` on overlay open + `batchPrefetchScores()` on stream-complete, sharing a `scoresCache` Map keyed `title|year` (region-independent, no country). Backend `/ratings` combines **OMDb** (RT critic Tomatometer, IMDb, Metacritic — `omdb.py`, optional, fail-soft) + **TMDB** `vote_average` (`fetch_movie_rating`, straight off the search result — no detail call). Absent scores are omitted; a TMDB `vote_average` of 0 ("no votes") is treated as absent, not shown as `0.0`. **Naming**: "certification" = the MPAA G/PG/R chip; "score(s)" = these review scores — the two are deliberately kept lexically distinct (see the certification-naming refactor). **Glyphs**: inline `<svg><symbol>` brand marks — IMDb/TMDB wordmarks and the RT tomato are simplified approximations, while the Metacritic "m" monogram (gold ring + dark field + stepped white "m", square `0 0 40 40` viewBox) carries the **official vector paths**, since its letterform cannot be reproduced with a font glyph. Each is an `<a>` opening the provider page in a new tab (`rel="noopener noreferrer"`) with the provider name as a hover `title`. **Deep links vs search**: IMDb (via OMDb's `imdbID`) and TMDB (via id) link straight to the film's page; RT and Metacritic have no stable per-title id in our data, so their glyphs link to the provider's **search results** for the title (always valid, never a guessed-slug 404). Mock (`__mock__`) results carry an inline `scores` array so the section renders fully without a backend.

## Deferred Ideas
- **Genre-metadata backfill for filtered anchor retrieval**: Hard filters (genre/year/cert) run *post-retrieval* in Python (`apply_hard_filters`) because genres live only in each vector's `document` text, not as filterable vector metadata. For reference-anchor queries with a *structured* qualifier (e.g. "like Inception but animated"), this forces us to over-fetch (`ANCHOR_FETCH_DEPTH`) and filter down — which trades precision for recall as depth grows, and can never manufacture similarity that isn't there. **If such queries prove common in the logs**, the precise fix is to add `genres` to vector metadata and use a metadata-filtered `vector_query` (`where={genre: ...}`) to retrieve the top-N genre-matching neighbors *directly*, full precision, no depth gamble. Follow the `backfill_certifications.py` pattern — it patched certification into existing Pinecone vectors without re-embedding; a genre backfill would be idempotent and identical in shape. Not worth doing until demand is demonstrated; tonal qualifiers ("funnier", "darker") are handled by Claude's rerank and need no metadata.
